### 断线重连竞态修复
- 根因：服务端在 WebSocket `connection` 事件中立即发送带临时 userId 的 `hello`，客户端收到后覆盖了 localStorage 中保存的正确 userId，导致重连用错 ID 找不到座位。
- 服务端修复：延迟 200ms 发送 hello，若客户端先发来 reconnect/hello 则取消延迟 hello。
- 客户端修复：新增 `reconnectInFlight` 标志，重连进行中不从 `hello` 覆盖 `reconnectUserId`；`open` 回调始终发送 hello/reconnect（不再静默）。
- App 层修复：用 `wasReconnecting` ref 避免 React 闭包陈旧值问题，重连成功后自动 `requestSync` 刷新房间视图。
- `handleReconnect` 增加日志便于生产排障。
